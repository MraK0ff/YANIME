Интерпретация:

- 160 upstream-коммитов уже входят в базу реконструкции; повторно cherry-pick-ать их нельзя и не нужно.
- 398 совпадающих путей уже имеют одинаковое итоговое содержимое в YANIME и upstream. Повторно переносить эти изменения не требуется.
- 376 fork-only путей являются кандидатами на перенос, но перед массовым применением нужно проверить существующие зависимости, удалённые пути и конфигурацию.
- 301 пересекающийся путь требует трёхстороннего анализа: общей версии, старой YANIME-версии и upstream 1.31.0. Простая замена одной стороны другой здесь недопустима.
- 408 upstream-only путей уже представлены в upstream-базе и должны остаться нетронутыми.

## Проверка идентичности и обновлений

На старой YANIME main подтверждены следующие значения:

- Application ID: `app.yanime`.
- GitHub Releases для автообновления: `MraK0ff/YANIME`.
- APK: `YANIME.apk`.
- Схема версий и beta-канала документирована в `docs/beta-updates.md`.
- CI использует отдельную конфигурацию `releaseDebug`, проверку Kotlin, сборку APK и сохранение R8 mapping.

В upstream-базе эти значения отличаются: application ID оригинала, репозиторий Helandy/YummyTV и upstream workflow. Поэтому перенос upstream build-конфигурации без адаптации неприемлем.
