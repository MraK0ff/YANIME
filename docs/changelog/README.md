# История изменений YANIME

Файл `yanime.json` — основной источник курируемой истории версий YANIME.
Для каждой версии добавляйте отдельный объект в массив `releases`.

## Обычные записи

Поле `notes` содержит короткие пользовательские изменения. Пишите по-русски,
начинайте с результата для пользователя и избегайте внутренних технических
подробностей. Один пункт — одно самостоятельное изменение.

## Привязка записи к коммиту

Если пункт относится к конкретному коммиту, добавьте его в
`commit_overrides` внутри объекта нужной версии:

```json
{
  "sha": "98adb1e156b357f665ae35c3be4d6ffdda19154e",
  "tag": "UI",
  "title": "Фильтр серий: сохранение выбранного режима и позиции списка",
  "description": "Выбранный режим сохраняется между запусками приложения. При переключении фильтров список возвращается к той же серии."
}
```

- `sha` — полный SHA коммита из GitHub, без URL.
- `tag` — исходный тег коммита без квадратных скобок. Не переименовывайте его.
- `title` — новая формулировка вместо исходного заголовка коммита.
- `description` — необязательное короткое пояснение; можно опустить.

Такой текст заменяет заголовок и описание исходного коммита в автоматически
собираемой истории и карточке релиза GitHub. В приложении он отображается
в истории версии, к которой привязан. Тег коммита сохраняется.

## Стиль текста и связь с коммитами

Используйте точный стиль заголовков Helandy/YummyTV: `[КАТЕГОРИЯ] Область: краткое описание на русском`.
Примеры: `[FEATURE] Расписание: фильтр «В библиотеке»`, `[BUGFIX] Плеер: исправлено восстановление после ошибки потока`,
`[UI] Библиотека (мобилка): строка сортировки скрывается при прокрутке`.

- Не используйте Conventional Commits, произвольные префиксы или английские заголовки.
- Один коммит соответствует одной самостоятельной пользовательской функции/исправлению. Несколько небольших технических шагов одной функции объединяйте.
- `[INTERNAL]` — только служебные изменения без пользовательской ценности; не включайте их в пользовательские заметки.
- Для пользовательских изменений обновляйте `docs/changelog/yanime.json` в записи нужной версии. `notes` — короткие и понятные пользователю пункты.
- Если требуется заменить автоматически извлечённое название конкретного коммита, используйте `commit_overrides`; SHA должен быть полным, а `tag` — исходной категорией без квадратных скобок.
- После изменения функций актуализируйте `README.md`: реализованное — в «Особенности форка», незавершённое — в «Планы форка».
- Реестр собственных коммитов и upstream-синхронизаций ведётся в `docs/changelog/commit-history.md`.

Заголовок не заканчивается точкой. Описание заметки должно объяснять результат для пользователя, а не пересказывать реализацию.
